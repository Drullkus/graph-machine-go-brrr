## `jdeps_to_graph.py`: from edge list to clusters

**1. Build the undirected graph**

$$W_{ij} = W_{ji} = 1 \iff \text{class } i \text{ references class } j, \qquad d_i = \sum_j W_{ij}$$

The directed "A uses B" rows from jdeps become one symmetric matrix, because the embedding only cares about who is connected, not who calls whom.

- Self-edges are dropped. Nested classes were already folded into their outer class upstream.
- A depth-first search finds connected components. Only the largest one is embedded. A disconnected graph gives extra zero eigenvalues that carry no position information, so the stragglers are excluded here and placed on a ring later.

**2. Normalize by degree**

$$N = D^{-1/2}\, W\, D^{-1/2}, \qquad \mathcal{L} = I - N$$

Dividing each edge weight by the square root of both endpoint degrees stops hub classes with hundreds of references from dominating every axis.

- $\mathcal{L}$ is the normalized Laplacian. The code works with $N$ directly and converts: large eigenvalues of $N$ are small eigenvalues of $\mathcal{L}$.
- The `--raw-laplacian` flag swaps in $L = D - W$ for comparison. Its docstring says it plainly: hubs dominate.

**3. Eigen-decomposition**

$$\mathcal{L}\, v_k = \lambda_k\, v_k, \qquad 0 = \lambda_0 \le \lambda_1 \le \lambda_2 \le \dots$$

This finds the smoothest possible "numberings" of the classes, where smooth means connected classes get nearly the same number.

- Intuition for why: for any vector $v$ that assigns one number per class,
  $$v^\top \mathcal{L}\, v = \sum_{(i,j) \in E} \left( \frac{v_i}{\sqrt{d_i}} - \frac{v_j}{\sqrt{d_j}} \right)^2$$
  measures the total disagreement across edges. An eigenvector with a small $\lambda$ is a numbering with little disagreement. Classes that reference each other land near each other on that axis.
- $\lambda_0 = 0$ belongs to the constant vector, which gives every class the same number. It is skipped.
- The next 8 eigenvectors are kept (`--dims`). Dense `eigh` on an $m \times m$ matrix is the slow step.

**4. Spectral coordinates**

$$x_i = \left( \frac{v_{1,i}}{\sqrt{d_i}},\ \frac{v_{2,i}}{\sqrt{d_i}},\ \dots,\ \frac{v_{8,i}}{\sqrt{d_i}} \right), \qquad \text{then each column rescaled to } \lVert X_{:,k} \rVert = 1$$

Multiplying back by $D^{-1/2}$ undoes the normalization so the result is the random-walk eigenvector, which is the standard choice for clustering, and the column rescale puts all axes on one scale.

- The first three columns are written as `e1, e2, e3` in `nodes.csv`.
- These coordinates are not final positions. Most classes pile into a small central blob with a few outliers stretching the axes. The `axis_stats` printout quantifies this: it reports how many blocks wide the world would be if the two closest classes sat one block apart.

**5. Project to the sphere and run k-means**

$$\hat{x}_i = \frac{x_i}{\lVert x_i \rVert}, \qquad \min_{C_1, \dots, C_k} \sum_{j=1}^{k} \sum_{i \in C_j} \lVert \hat{x}_i - \mu_j \rVert^2$$

Row-normalizing first makes k-means group by direction from the blob center rather than by distance from it, which is the Ng, Jordan and Weiss recipe for spectral clustering.

- Seeding is k-means++: each new center is drawn with probability proportional to squared distance from the nearest existing center.
- Up to 100 Lloyd iterations: assign each point to its nearest center, then move each center to the mean of its points.
- $k = 40$ by default. Purity against depth-3 package names is printed as a sanity check that the clusters resemble how the code is actually organized.

**6. Aggregate edges to the cluster level**

$$E_{ab} = \#\{(i, j) \in E : c_i = a,\ c_j = b\}$$

This count of class edges between each cluster pair becomes the attraction weight in the next script.

## `layout_graph.py`: from clusters to block positions

**7. Size a disc per cluster**

$$r_c = 1.25\, s\, \sqrt{\frac{n_c}{\pi}}$$

A disc of this radius has area for $n_c$ classes at spacing $s$, with 25 percent slack.

- Start positions are the mean $(e_1, e_2)$ of each cluster's members, stretched so the discs roughly fit, plus a little noise.

**8. Cluster-level force simulation**

With $t_{ab} = r_a + r_b + 2s$ as the touching distance and $d_{ab}$ the current distance:

$$F_{\text{rep}} = 2 \max(0,\ t_{ab} - d_{ab}) + 0.2\, s \left( \frac{t_{ab}}{d_{ab}} \right)^2$$

$$F_{\text{att}} = 0.5 \sqrt{\frac{E_{ab}}{E_{\max}}}\ \operatorname{clip}(d_{ab} - t_{ab},\ 0,\ 4s)$$

$$P \leftarrow P + \min(\lVert F \rVert,\ T)\, \hat{F}, \qquad T = r_{\max}\left( 1 - \frac{it}{\text{iters}} \right) + 0.05$$

Discs that overlap shove apart hard, discs that share many class edges pull together, and the pull saturates so a well-connected cluster cannot drag neighbors on top of itself.

- A weak pull of $-0.02 P$ toward the origin keeps the layout compact.
- $T$ is a cooling temperature. Early steps can move a disc by a full radius. Late steps barely move at all, so the layout settles.
- After the simulation, a hard pass repeats "push overlapping pairs apart by 55 percent of the overlap" until no pair overlaps.
- Cluster height is the rank of its mean $e_3$ scaled to $\pm \text{height}/2$, so the result is mostly flat.

**9. Seed classes inside their disc by rank**

$$u_i = 2 \frac{\operatorname{rank}(e_{1,i})}{n_c - 1} - 1 \in [-1, 1], \qquad p_i = \text{center}_c + 0.8 \frac{r_c}{\sqrt{2}} (u_i,\ \cdot,\ v_i) + \text{jitter}$$

Ranks are used instead of the raw spectral values because many classes share identical spectral coordinates, and spreading them evenly by order avoids a pile at one point.

- $u$ comes from $e_1$ and goes to $x$, $v$ from $e_2$ goes to $z$, and $w$ from $e_3$ goes to $y$ with the height scale.
- Ties are broken by a tiny random noise term. Jitter is Gaussian with standard deviation $0.1 s$.

**10. Class-level force simulation**

Three forces act on every class in every step.

Spring along each edge, weaker when either endpoint is a hub:

$$F_{\text{spring}} = h_{ij} \min\left( \frac{d_{ij}}{s},\ 4 \right) \hat{d}_{ij}, \qquad h_{ij} = \big( (\deg_i + 1)(\deg_j + 1) \big)^{-1/4}$$

Repulsion between any pair closer than the cutoff $c = 2.5 s$:

$$F_{\text{rep}} = 1.5 \left[ \left( \frac{s}{d} \right)^2 - \left( \frac{s}{c} \right)^2 \right] \hat{d}$$

Gravity toward the cluster center, with a soft wall at the disc edge, where $\rho$ is the horizontal distance to the center:

$$F_{\text{grav}} = \left( g \frac{\rho}{r_c} + 2 \max(0,\ \rho - r_c) \right) \hat{d}_{\text{center}}$$

Update, with vertical motion damped by `vscale`:

$$F \leftarrow 0.2 \cdot (1,\ v,\ 1) \odot F, \qquad P \leftarrow P + \min(\lVert F \rVert,\ T)\, \hat{F}, \qquad T = s \left( 3 (1 - \text{progress})^2 + 0.02 \right)$$

Springs pull referenced classes together, repulsion keeps everything at least a spacing apart, and gravity keeps each class inside its own disc so clusters stay as readable clumps.

- The repulsion subtracts $(s/c)^2$ so the force reaches exactly zero at the cutoff instead of jumping, which avoids jitter.
- Without the hub factor $h_{ij}$ a class referenced by 500 others would pull them all into a ball around itself.
- Pair finding uses a uniform grid with cell size equal to the cutoff. Only the 27 cells around each node are checked, so each step is linear in node count rather than quadratic.
- `vscale` of 0.25 means a class moves vertically at a quarter of the rate it moves horizontally. This gives gentle hills instead of a cloud.

**11. Hard separation pass**

$$d_{ij} < m \implies p_i \leftarrow p_i - 0.55 (m - d_{ij})\, \hat{d}_{ij}, \quad p_j \leftarrow p_j + 0.55 (m - d_{ij})\, \hat{d}_{ij}$$

Forces only approach a balance, so this position-based pass guarantees the promise that no two classes end closer than one block.

- $m = 1.02 \times$ `--min-dist`. The 2 percent margin stops pairs sitting right at the limit from trading places forever.
- Each node moves 55 percent of the gap, so a pair overshoots slightly and resolves in one pass instead of converging asymptotically. Up to 200 passes.

**12. Place isolated classes and recenter**

$$p_i = \left( \bar{x} + R \cos \theta_i,\ 0,\ \bar{z} + R \sin \theta_i \right), \qquad R = \max_j \rho_j + 6s, \qquad \theta_i = \frac{2\pi i}{n_{\text{iso}}}$$

Classes with no edges never entered the simulation, so they are spaced evenly on a ring just outside the main layout, and then the whole layout is shifted so the main part is centered on the origin.

- The final `layout.csv` holds `class, x, y, z` in block units with `y` vertical.

**The one-paragraph version for friends.** Spectral embedding asks: what is the smoothest way to assign a number to each class so that classes referencing each other get nearly the same number? The eigenvectors of the normalized Laplacian answer that question, and the first few of them give every class a point in space. K-means groups those points into 40 clusters. Then a physics simulation runs twice: once with clusters as discs that repel when they touch and attract when their classes reference each other, and once with the individual classes inside those discs, connected by springs, pushed apart at short range, and held in place by gravity toward their cluster center. A final pass enforces the one-block minimum distance.

**Your three questions**

**D is the degree matrix, but degree counts both directions.** Step 1 made the graph undirected, so $d_i$ is the number of distinct classes connected to $i$ either way. MudBlock has degree 10: it references 9 classes and Blocks references it. $D$ is the diagonal matrix with those numbers, and everything off the diagonal is zero.

**The square root is there to keep the matrix symmetric.** The natural way to tame hubs is to divide each row of $W$ by its degree, giving $D^{-1} W$. Row $i$ then sums to 1, so a class with 500 connections spreads its influence thin instead of dominating. The problem is that $D^{-1} W$ is not symmetric, and your linear algebra course will have shown why that hurts: only symmetric matrices are guaranteed real eigenvalues and orthogonal eigenvectors. Splitting the division into two halves fixes it:

$$N_{ij} = \frac{W_{ij}}{\sqrt{d_i}\sqrt{d_j}}$$

Entry $ij$ and entry $ji$ get the same value, so $N$ is symmetric and numpy's `eigh` applies. The two matrices have the same eigenvalues, and their eigenvectors differ by exactly the factor $D^{-1/2}$. That is why step 4 multiplies by $1/\sqrt{d_i}$ afterward: it converts the eigenvector of the symmetric $N$ back into the eigenvector of the hub-tamed $D^{-1} W$, which is the one that clusters well.

**"Large eigenvalues of $N$ are small eigenvalues of $\mathcal{L}$" is one line of algebra.** If $N v = \mu v$, then

$$\mathcal{L} v = (I - N) v = v - \mu v = (1 - \mu)\, v$$

Same eigenvector, eigenvalue $1 - \mu$. The eigenvalues of $N$ sit in $[-1, 1]$. Its biggest, $\mu = 1$, is the useless constant vector with $\lambda = 0$. Its next biggest are the ones we want. The code hands $N$ to `eigh`, which returns eigenvalues in ascending order, so it reverses the list and reports $1 - \mu$ as the Laplacian eigenvalue.

**The piece that makes the later steps click.** For a symmetric matrix, an eigenvector is a direction the matrix only stretches, and for a unit-length eigenvector the eigenvalue equals $v^\top \mathcal{L} v$. For this particular matrix that quantity is a sum over edges of squared differences, so the eigenvalue literally measures how much the numbering $v$ disagrees along edges. The eigenvector with the smallest nonzero eigenvalue is therefore the least-disagreeing numbering that is not constant. It must take both positive and negative values, so it splits the graph in two along its weakest seam. The next eigenvector splits it a different way, and so on. Eight eigenvectors give each class eight "which side of the seam" scores, and k-means groups classes with similar scores.

**Why MudBlock sits next to CatLieOnBlockGoal**

Their rows of $N$ are nearly identical, so every eigenvector assigns them nearly the same score. The math is saying "these are all generic leaves hanging off the same core types," which is true but useless for navigation.
- With 8 eigenvectors you get at most about 8 seams. Each seam tends to peel off one tightly knit peripheral module and leave everything else at zero. Eight seams cannot separate 40 groups, so k-means slices the peripheral modules finely and dumps the core into one bin.
