# Graduate from display entities: instanced graph renderer + ImGui inspector panel

## Context

The graph is currently placed as one block display and two text displays per class (6,736 classes), saved into chunks by `GraphChunkGenerator`. That forces nodes apart so labels do not overlap, tanks FPS when many are on screen, and leaves no room for the 84,600 edges. This change moves all drawing to the client: nodes, labels and edges become instanced geometry drawn with `drawIndirect` from compacted GPU buffers, and a Dear ImGui panel locked to the right side of the window (Unity Inspector style) controls what is shown. The main Minecraft framebuffer shrinks so the panel owns its strip of the window, and the panel scales with the display's pixel density, never with GUI Scale.

Decisions already made with the owner (AskUserQuestion rounds):

| Topic | Decision |
|---|---|
| Visibility to GPU | Indirect draws from CPU-compacted instance buffers; rebuild spread over frames |
| Labels | Vanilla font glyphs, instanced per glyph |
| Edges | Instanced screen-space quads, constant pixel width, endpoint-cluster color gradient, ~60% alpha |
| Nodes | Flat colored cubes, per-cluster color, simple directional shading |
| Data location | Client assets (`assets/graphmachine/graph/`); server keeps only the floor |
| Edge file | `edges.bin`, little-endian int32 index pairs |
| Old worlds | Not migrated; entity placement removed, new world needed |
| When to draw | Level's dimension type is `graphmachine:graph` (new datagen'd dimension type) |

| Persistence | `config/graphmachine-client.json` through a Codec |
| Filter | Case-insensitive substring over the full class name; space-separated terms all must match |
| Excluded nodes | Hidden (left out of the compacted buffers), with their labels and edges |
| Apply phase | Worker thread builds arrays; render thread uploads a byte budget per frame, then swaps; footer shows "Applying changes" + progress |
| Hover | Nearest cube hit along the crosshair ray (cursor ray when a screen is open); hovered node brightens, its edges go full alpha and double width via a uniform |

/**
 * Development aid: with the system property {@code graphmachine.autoScreenshot=N} set, saves one PNG of
 * what the window shows (the composite with the panel, or the main render target) to
 * {@code screenshots/graphmachine-auto.png} N seconds after the graph first finished applying. The
 * {@code clientGraph} run sets the property so the renderer can be checked without touching the game.
 *
 * <p>Written by Claude Code; conversation transcript: {@code $T}.
 */
final class AutoScreenshot {
    private static final String PROPERTY = "graphmachine.autoScreenshot";
    private static final String FILE_NAME = "graphmachine-auto.png";

    private final long delayMs;
    private long readySinceMs = -1;
    private boolean taken;

    private AutoScreenshot(long delayMs) {
        this.delayMs = delayMs;
    }

    /** The helper when the property is set, else null. */
    static @Nullable AutoScreenshot fromSystemProperty() {
        String value = System.getProperty(PROPERTY);
        if (value == null) {
            return null;
        }
        try {
            return new AutoScreenshot(Math.round(Double.parseDouble(value) * 1000.0));
        } catch (NumberFormatException e) {
            GraphMachine.LOGGER.warn("Ignoring {}={}: not a number of seconds", PROPERTY, value);
            return null;
        }
    }

    /** Call once per frame after the compositor ran. */
    void onFrameEnd(GraphRenderer renderer) {
        if (this.taken) {
            return;
        }
        if (renderer.frontView() == null || renderer.applying()) {
            this.readySinceMs = -1;
            return;
        }
        long now = Util.getMillis();
        if (this.readySinceMs < 0) {
            this.readySinceMs = now;
            return;
        }
        if (now - this.readySinceMs < this.delayMs) {
            return;
        }
        this.taken = true;
        GpuTexture texture = PanelCompositor.compositeView() != null ? PanelCompositor.compositeView().texture() : Minecraft.getInstance().gameRenderer.mainRenderTarget().getColorTexture();
        if (texture == null) {
            return;
        }
        File file = new File(Minecraft.getInstance().gameDirectory, "screenshots/" + FILE_NAME);
        save(texture, file);
    }

    private static void save(GpuTexture texture, File file) {
        int width = texture.getWidth(0);

---
name: mc-26-3-render-notes
description: "Minecraft 26.3 / NeoForge 26.3.0.76 render API facts learned while building the instanced graph renderer and the ImGui panel (indirect draws, fonts, framebuffer, mixin targets, datagen classpath)"
metadata:
  type: project
---

Render-side facts for Minecraft 26.3 with NeoForge 26.3.0.76, verified in-game on 2026-10-16 (macOS, OpenGL 4.1 backend):

- `RenderPass.drawIndirect(GpuBufferSlice, drawCount)` works; `DeviceFeatures.drawIndirect()` is true on macOS GL, `multiDrawIndirect` and `nonZeroFirstInstance` are false. No compute shaders, no SSBO `UniformType`.
- Per-instance streams: `VertexFormat.builder(1)` at binding 0 works with no per-vertex binding at all; geometry from `gl_VertexIndex` / `gl_InstanceIndex` (shaders are compiled to SPIR-V by shaderc for both backends, so use the Vulkan names).
- Every uniform a pipeline's bind group layouts declare must be set before a draw (`FrontendRenderPass` throws "Missing uniform"); extra `setUniform` names are harmless.
- `MappableRingBuffer` requires `USAGE_MAP_READ` or `USAGE_MAP_WRITE` in its usage flags even when written with `writeToBuffer`.
- The default font's ASCII page is `RGBA8_UNORM` (bitmap fonts with more than one channel count as "colored"), not R8; coverage is in alpha.
- `RenderLevelStageEvent.AfterTranslucentBlocks` only fires with classic transparency; `AfterOpaqueBlocks` and `AfterOpaqueFeatures` fire in both paths.
- The swapchain blit lives in `Minecraft.renderFrame`, not `runTick`; it copies the texture 1:1 at the top-left with no scaling. `Window.framebufferWidthPadding()` is subtracted from the framebuffer width, so a `@ModifyReturnValue` on it narrows the main target and GUI.
- The `data` run uses the datagen source set's classpath: `datagenImplementation.extendsFrom implementation` is needed when the client mod class touches a library (imgui-java) in its constructor, and the GPU device does not exist there, so never create GPU objects in mod constructors.
- `--quickPlaySingleplayer <name>` loads a save at launch; a save's dimension settings live in `data/minecraft/world_gen_settings.dat`, not `level.dat`. The project's `runClientGraph` run plus `graphmachine.autoScreenshot` gives a PNG without touching the game.

**Why:** Each of these cost a failed compile, a crashed datagen run, or an empty render during the session that built the renderer ([[mc-26-3-api-notes]] has the worldgen-side list).

**How to apply:** Check this list before touching the renderer, the panel compositor or the mixins, and extend it when a new 26.x surprise shows up.
