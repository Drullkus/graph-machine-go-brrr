## Script review

What the script gets right:

- **`-verbose` is the correct flag.** It means class-level output with no filtering. The earlier `-verbose:class` applied the default same-package filter, which silently dropped most of the edges that make clumps. Commit 3ef94f6 fixed that correctly.
- **The committed dot file matches a fresh run** line for line, and the jar is not multi-release, so no extra flags are needed.
- **jdeps captures what you want.** Every type a compiled class names in its constant pool, field and method signatures, generics and annotations becomes an edge. That is a complete static "A mentions B" relation.

What I would fix:

1. **Half the file is noise for this project.** Of the edges, only those whose target is tagged with the jar name matter. Everything else points at the JDK or at libraries that are not in the jar. Filtering with jdeps's own `-e` regex does not help enough, because Brigadier and DataFixerUpper live under `com.mojang` and still leak through. Filter in post-processing on the archive tag instead.

## The graph in matrices

Your edge list already is a matrix. It is just written as a list of the nonzero cells.

**Adjacency matrix A.** One row and one column per class. Cell (i, j) is 1 if class i references class j, else 0. Row i is "what i uses", column j is "who uses j". For clumping you want "related in either direction", so make it symmetric: W = A + Aᵀ, clipped to 1. That is a plain lookup table, nothing more.

**Degree matrix D.** Only the diagonal is used. Cell (i, i) is the number of neighbors of i, which is the sum of row i of W.

**Laplacian L = D − W.** This is the one that matters, and one fact makes it click. Suppose you give every class a number x_i, say its x-coordinate in the world. Then:

```
xᵀ L x  =  sum over every edge (i, j) of  (x_i − x_j)²
```

So L is a machine that scores a coordinate assignment by how much neighbors disagree. Low score means connected classes sit close together. That is exactly your goal, stated as arithmetic.

**Eigenvalues, from scratch.** A matrix is a function that moves vectors. Most vectors get turned when you apply it. An eigenvector is a direction the matrix does not turn, only stretches, and the eigenvalue λ is the stretch factor. For L, take an eigenvector x with unit length. Then xᵀ L x equals λ. So each eigenvalue of L is the disagreement score of its eigenvector, read as a coordinate assignment. Sorting the eigenvalues from small to large sorts the assignments from smoothest to roughest.

The smallest eigenvalue is always 0. Its eigenvector gives every class the same number, which has zero disagreement and is useless. The second smallest is the smoothest assignment that is not constant. That vector, called the Fiedler vector, is a one-dimensional layout where neighbors land near each other. The third and fourth eigenvectors give you y and z. Running k-means on those coordinates is spectral clustering. A bonus fact: the number of zero eigenvalues equals the number of connected components, and your graph has exactly one.

The three values A, B, C are negative and D, E, F are positive, so a single eigenvector already found the two clumps. The matrix never saw the picture. It only saw which pairs are connected.

**Hubs need normalization.** With raw L, a class like `BlockPos` with 1,365 neighbors dominates the scoring and every eigenvector ends up describing the hubs. Dividing by degree fixes this: L_sym = D^(−1/2) L D^(−1/2). The intuition is a random walk. Start at a class and hop to a random neighbor repeatedly. The normalized eigenvectors describe where a walker tends to get stuck, and walkers get stuck inside clumps. The prototype used this form.

**Your exact criterion is a matrix product.** You said classes should clump when they reference similar classes. Cell (i, j) of A·Aᵀ is the number of classes that both i and j reference. Cell (i, j) of Aᵀ·A is the number of classes that reference both i and j. Those two products are co-citation and bibliographic coupling from citation analysis, and you can feed either, or their sum with the direct edges, into W before building L. Direct edges alone already gave good clumps, so start there.

**Incidence matrix B.** One row per node, one column per edge, with +1 at one end and −1 at the other. Its only role here is that B·Bᵀ = L, which is the matrix-algebra proof of the disagreement formula above. You do not need it in code.

**What the real data did.** The ten smallest normalized eigenvalues were 0, 0.031, 0.058, 0.086 and then a slow climb. The Fiedler axis put the DataFixerUpper schema classes at one end and the baby-animal animation definitions at the other, which is correct and funny. Clustering on the first 8 eigenvectors worked well, with clusters that are clearly "level", "GUI plus Realms", "renderer plus model", "entity", "datafix", "network protocol" and "commands". **Recommended pipeline for the mod.** Precompute offline, ship positions as a resource:

1. Build W from the filtered edge list, collapsing nested classes.
2. Compute the first 8 to 16 eigenvectors of the normalized Laplacian. Dense numpy took 42 seconds for 6,723 nodes on your Mac. With scipy installed, a sparse solver does it in a second or two.
3. k-means on those eigenvectors gives clusters, with k around 40.
4. Lay out clusters with a force-directed algorithm, then classes within each cluster the same way, seeded from the spectral coordinates. Force-directed layout is what Gephi and most graph tools use for the final picture. Spectral gives it a sensible start and the cluster membership.
5. Render in-game. 6,723 display entities is feasible. 84,633 edge entities is not, so draw edges only for the class the player is looking at or standing in.

 * the {@code data} run sets in {@code build.gradle}. A class without a layout row is skipped with a warning.
 *
 * <p>Written by Claude Code; conversation transcript: {@code llm/transcripts/transcript_2026-10-16_07-43_2aec7285-4ea5-4d89-ba3e-f516a9a7bde0.md}.
 */
public final class GraphDataProvider implements DataProvider {
    public static final String INPUT_PROPERTY = "graphmachine.graphData";

    private final PackOutput output;

    public GraphDataProvider(PackOutput output) {
        this.output = output;
    }

    @Override
    public CompletableFuture<?> run(CachedOutput cache) {
        Path inputDir = Path.of(System.getProperty(INPUT_PROPERTY, "graph-data"));
        GraphData data = read(inputDir.resolve("nodes.csv"), inputDir.resolve("layout.csv"));
        Path target = this.output.getOutputFolder(PackOutput.Target.DATA_PACK)
                .resolve(GraphDataLoader.FILE.getNamespace())
                .resolve(GraphDataLoader.FILE.getPath());
        return DataProvider.saveStable(cache, GraphData.CODEC, data, target);
    }

    @Override
    public String getName() {
        return "Graph nodes";
    }

    /** Reads both CSV files and joins them on the class name. */
    static GraphData read(Path nodesCsv, Path layoutCsv) {
        Map<String, float[]> positions = new HashMap<>();
        for (String[] row : rows(layoutCsv)) {
            positions.put(row[0], new float[] {Float.parseFloat(row[1]), Float.parseFloat(row[2]), Float.parseFloat(row[3])});
        }
        List<GraphNode> nodes = new ArrayList<>();
        for (String[] row : rows(nodesCsv)) {
            String className = row[0];
            float[] position = positions.get(className);
            if (position == null) {
                GraphMachine.LOGGER.warn("Class {} has no row in {}; skipped", className, layoutCsv);
                continue;
            }
            GraphNode.Side side = row[1].equals("client") ? GraphNode.Side.CLIENT : GraphNode.Side.COMMON;
            nodes.add(new GraphNode(className, position[0], position[1], position[2], Integer.parseInt(row[4]), side, Integer.parseInt(row[2])));
        }
        nodes.sort(Comparator.comparing(GraphNode::className));
        return new GraphData(nodes);
    }

    /** The data rows of a CSV file without quoting, header line dropped. */
    private static List<String[]> rows(Path csv) {
        try {
            List<String> lines = Files.readAllLines(csv);
            List<String[]> rows = new ArrayList<>(lines.size());
            for (int i = 1; i < lines.size(); i++) {
                String line = lines.get(i);
                if (!line.isBlank()) {
                    rows.add(line.split(","));
                }
            }
            return rows;
        } catch (IOException e) {
            throw new UncheckedIOException("Cannot read " + csv, e);
        }
    }
}
